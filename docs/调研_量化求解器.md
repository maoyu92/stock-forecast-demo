# 调研报告：量化/证券领域的"求解器"

> 调研日期：2026-09-13
> 背景：同行反馈"现有预测类策略对复杂场景不太有用"，建议围绕**求解器**思考；且量化涉及**多账户同时操作**。本文回答三个问题：① 股市语境下"求解器"到底指什么；② 有哪些开源求解器；③ 有哪些大厂闭源但开放 API 的求解器/优化服务。最后结合本项目（A 股 + TimesFM 预测 Demo）给选型建议。

---

## 1. 一句话结论（TL;DR）

- 证券语境的"求解器"≈**数学优化求解器**（运筹学求解器）：给定目标函数和一堆约束，在毫秒~秒级算出"最优的一组数"（仓位权重、每账户每笔的下单量）。
- 同行那句话的实质：**预测模型只解决"买什么/看哪个方向"，而复杂场景（多账户、资金约束、整手、冲击成本、合规限制）的核心瓶颈在"优化层"——把信号变成一组合法的、成本最优的订单**。这一层国际头部量化的标准做法就是"组合优化器 + 执行求解器"。
- **开源完全够起步**：HiGHS、Google OR-Tools、OSQP、CVXPY 生态、skfolio/Riskfolio-Lib，全部免费且工程成熟；国产 MindOpt（阿里）还有**免费云端 API**（1 并发 0 元）。
- **闭源但开放 API** 分两档：通用求解器（Gurobi / Mosek / COPT / MindOpt / 华为天筹，提供 Python SDK 或云 API，约 1 万美元/年或国产低价）；机构级**组合优化器**（MSCI Barra、Axioma/SimCorp，可经 FactSet Open:Optimizer API 调用，仅对机构客户开放）。
- 对多账户 A 股场景的建议：先上 **CVXPY + OSQP/HiGHS 的两级优化**（组合层 → 账户分配层 → 执行拆单层），验证价值后再考虑 COPT/Gurobi。

## 2. "求解器"在股市里是什么意思

### 2.1 两种常见含义

| 含义 | 别称 | 解决的问题 | 典型响应时间 |
|---|---|---|---|
| **数学优化求解器**（本报告主线） | 组合优化器、运筹求解器 | 在约束下最大化/最小化一个目标函数，输出"最优权重/最优订单" | 秒级（组合层）到毫秒级（执行层） |
| **执行算法/智能路由**（广义的"执行求解器"） | SOR（智能订单路由）、TWAP/VWAP/冰山 | 把一个大单拆成小单，最小化市场冲击与滑点 | 毫秒级、持续滚动 |

另有一些更窄的用法（期权定价里的 PDE 求解器、蒙特卡洛引擎等），不在本报告范围。同行说"围绕求解器考虑"，结合"多账号同时操作"的语境，指的几乎肯定是第一类 + 第二类的组合。

### 2.2 在量化流水线中的位置

```
数据/因子 → 预测模型(TimesFM 等, 产生 alpha 信号)
                ↓
        【组合优化器】  ← 目标: 最大化 alpha - 风险成本 - 交易成本
                ↓           约束: 风格敞口、行业、个股权重上限、换手率、流动性
        目标持仓（每个账户一份）
                ↓
        【多账户分配求解】 ← 把总订单按各账户资金/持仓/限制切分（MILP）
                ↓
        【执行求解器】  ← 拆单算法 TWAP/VWAP/冰山，最小化冲击
                ↓
            券商柜台/PB 系统
```

明汯投资对"优化器"的公开解释很直白：优化器就是**在给定约束条件下计算目标函数最大值、生成具体仓位权重**的那一层，是信号（alpha）与真实持仓之间的翻译官（[中证网·明汯投教](https://www.cs.com.cn/ssgs/gsxl/202311/t20231127_6377848.html)）。头部资管如 Robeco 公开分享过从开源/商业求解器迁移到 Gurobi 做组合优化的案例（[知乎·Gurobi 案例](https://zhuanlan.zhihu.com/p/397186959)）。

**为什么"复杂场景"下预测策略"没用"**：预测只回答 P(涨跌)，但真实下单时要同时回答——买多少（仓位）、几个账户怎么分（资金约束）、一次买还是分批买（冲击成本）、涨跌停/T+1/整手怎么办（可行性约束）。这些问题没有解析解，本质都是优化问题，必须靠求解器。策略"简单"不是问题，**缺少把策略转化为合法订单的优化层**才是复杂场景下失效的原因。

### 2.3 股市里的四类典型优化问题

| 问题 | 数学形式 | 典型规模 | 响应要求 |
|---|---|---|---|
| **组合构建**（均值-方差、最大化效用-风险） | 凸 QP / SOCP（协方差矩阵） | 数百~数千只股票 | 盘中秒级 / 盘后分钟级 |
| **指数增强 / 跟踪误差最小化** | QP + 换手约束 | 同上 | 同上 |
| **多账户订单分配**（本场景重点） | MILP（整手、账户限额引入整数变量） | 账户数 × 标的数（如 10 账户 × 500 标的） | 秒级 |
| **执行拆单**（最小化冲击） | 凸优化滚动求解 + 规则 | 单标的 | 亚秒级 |

**多账户分配问题的典型建模**（示意）：

```
min   Σ_i Σ_a impact(q_{i,a})            # 总冲击成本（可用分段线性/二次近似）
s.t.  Σ_a q_{i,a} = Q_i                  # 每只股票的总目标下单量
      q_{i,a} ∈ 100·Z                    # A股整手约束 → 整数变量 → MILP
      Σ_i q_{i,a}·p_i ≤ cash_a           # 每账户资金约束
      持仓限额、禁买名单、T+1 可卖数量     # 每账户线性约束
      申报频率 ≤ 合规上限                  # 程序化交易新规（见 §7）
```

规模在几千~几万个整数变量时，求解器选型直接决定能否在秒级出结果——这就是"围绕求解器"的工程含义。

## 3. 开源求解器

### 3.1 通用数学优化求解器（免费、可商用者已标注）

| 求解器 | 许可证 | 支持问题 | 强项与定位 |
|---|---|---|---|
| **HiGHS** | MIT | LP / MIP / 凸 QP | 开源里 LP/MIP 综合最强之一；**SciPy `linprog`/`milp` 的默认引擎**，MATLAB `intlinprog` 也基于它；被 Pyomo/PuLP 广泛集成（[GitHub](https://github.com/ERGO-Code/HiGHS)） |
| **Google OR-Tools** | Apache 2.0 | LP（Glop）、整数/约束（CP-SAT）、一阶 LP（PDLP） | **CP-SAT 是免费 MIP 的最强选择**，组合类问题（分配、调度）非常快；完全免费可商用 |
| **OSQP** | Apache 2.0 | 凸 QP | ADMM 算法、支持 warm-start，**特别适合实时/嵌入式再平衡**（毫秒级重解）；QPLIB 上大规模稀疏 QP 表现好 |
| **SCIP** | Apache 2.0（2022 起） | MIP / MINLP | 学术界最强 MIP 之一， formerly 学术免费现已开源 |
| **Clarabel** | Apache 2.0 | 凸锥（SOCP 等） | Rust 编写，CVXPY 新版默认求解器，数值稳定性好 |
| **SCS / ECOS** | MIT / GPL | 凸锥 | CVXPY 生态常用后端 |
| **Ipopt** | EPL | 非线性（NLP） | 连续非线性问题标配，金融里用得少 |
| **COIN-OR Clp/Cbc** | EPL | LP / MIP | 老牌，性能已被 HiGHS 超越，新项目不建议 |
| **NVIDIA cuOpt** | 开源（2025） | LP / 路由问题（GPU） | GPU 加速路线，NVIDIA 官方博客演示过用它做均值-CVaR 组合优化（[NVIDIA 博客](https://developer.nvidia.cn/blog/accelerating-real-time-financial-decisions-with-quantitative-portfolio-optimization/)），适合超大规模/低延迟场景探索 |

中科院战略研究报告对国产求解器的评价：**COPT（杉数）MIP 性能约为 Gurobi 的 1/2.13，高于 FICO Xpress，已达国际一流**（[中科院报告 PDF](http://academics.casad.cas.cn/zlyj/qyjcyp/202507/W020250726563774044220.pdf)）——这从侧面说明：开源 HiGHS/OR-Tools + 国产商业求解器已能覆盖大部分组合优化需求。

### 3.2 组合优化 / 执行层的开源上层库（调用上述求解器）

| 库 | 定位 | 依赖求解器 | 备注 |
|---|---|---|---|
| **CVXPY** | 凸优化建模 DSL（写数学公式一样建模） | Clarabel/OSQP/SCS/Mosek 可切换 | 金融优化建模事实标准；支持混合整数凸问题 |
| **skfolio** | 基于 scikit-learn 的组合优化库，自带交叉验证/防过拟合 | CVXPY | 最新、工程化程度高（[官网](https://skfolio.org/)、[论文](https://arxiv.org/html/2507.04176v2)） |
| **Riskfolio-Lib** | 风险度量最全（CVaR、方差、回撤等 30+ 种） | CVXPY | 学术味浓、功能全（[文档](https://riskfolio-lib.readthedocs.io/en/latest/)） |
| **PyPortfolioOpt** | 经典方法（均值-方差、Black-Litterman、HRP）入门首选 | CVXPY | 最流行但发展放缓（[文档](https://pyportfolioopt.readthedocs.io/)） |
| **cvxportfolio** | Stanford Boyd 团队的交易组合优化框架 | CVXPY | 有配套教材《Convex Optimization》 |
| **vn.py AlgoTrading** | **执行算法模块**：TWAP、Sniper、冰山(Iceberg)、BestLimit，可 UI/CSV 批量调用 | —（规则型） | 国内 A 股/期货生态最成熟的开源执行方案（[GitHub](https://github.com/vnpy/vnpy_algotrading)） |
| **Hummingbot** | 做市/执行框架（加密货币为主） | — | 思路可借鉴，不直接适用 A 股 |
| **QuantLib** | 定价库（内含 1-D 数值求解器） | — | 期权/固收方向才需要 |

**开源组合拳参考**：`CVXPY（建模） + HiGHS（盘后组合层 QP/MILP） + OSQP（盘中实时再平衡） + vn.py AlgoTrading（执行拆单）`——全程 0 许可费。

### 4.2 机构级"组合优化器"（金融专用、闭源、仅对机构开放）

这类不是裸求解器，而是**内置了 A 股/全球市场约束模板、风险模型对接、合规检查**的组合优化整体方案，是买方机构的标配：

| 产品 | 厂商 | 说明 |
|---|---|---|
| **Barra Open Optimizer / Barra PortfolioManager** | MSCI | 优化引擎 + Barra 风险模型一体（[产品页](https://www.msci.com/data-and-analytics/portfolio-management/barra-portfolio-manager)） |
| **Axioma Portfolio Optimizer** | SimCorp（原 Axioma） | 买方市占率最高的组合优化器之一，支持税务/ESG/多资产，与 FlexTrade 等 OMS/EMS 集成（[产品页](https://www.simcorp.com/solutions/axioma-solutions/axioma-portfolio-optimizer)） |
| **FactSet Open:Optimizer API** | FactSet | **同一套 REST API 统一调用 Axioma 和 Barra 两家引擎**——这是"闭源大厂开放 API"在组合优化领域的最佳实例（[API 目录](https://developer.factset.com/api-catalog/openoptimizer-api)） |
| Northfield 优化器 | Northfield | 老牌第三方，风格偏配置型 |

**获取门槛**：以上均无公开定价，需机构签约（通常绑定风险模型订阅，年费数万~数十万美元级）。个人/小团队拿不到，但值得知道天花板长什么样——A 股头部量化私募多用**自研优化器**（内核是 Gurobi/COPT/自研求解算法 + 自有风险模型）。

### 4.3 大厂金融科技服务（相关但不纯是求解器）

| 服务 | 厂商 | 说明 |
|---|---|---|
| **DolphinDB + Gurobi 插件** | 智臾科技 | 国产高性能行情/时序数据库，官方教程演示"Gurobi 求解 MVO 组合优化"，商业软件（[官方教程](https://docs.dolphindb.cn/zh/tutorials/MVO.html)） |

## 5. 与本项目的关系 & 选型建议

本项目现状：TimesFM 预测 Demo + 多策略选股 PRD。按照 §2.2 的流水线，**预测模型只是 alpha 输入**，要应对"多账户 + 复杂约束"场景，需要补的是中间的优化层。建议按三阶段走：

### 阶段一：开源起步（0 成本，1–2 周）
1. **组合层**：`CVXPY + HiGHS`。把 TimesFM 的预测收益率/波动作为输入，最小化 `风险 - 预期收益`，约束加上：个股权重上限、行业敞口、换手率惩罚。A 股 500 只标的的凸 QP，HiGHS 毫秒~秒级出解。
2. **整手化**：先用简单取整，够用；不够再上 `scipy.optimize.milp`（HiGHS 内核）解整手分配。
3. **执行层**：`vn.py AlgoTrading` 的 TWAP/冰山算法，或自写简化版按分钟切片。

### 阶段二：多账户 MILP（0 成本，验证核心价值）
- 用 **OR-Tools CP-SAT 或 HiGHS MIP** 建模 §2.3 的多账户分配问题（整手 100 股 → 整数变量；每账户资金/持仓/禁买 → 线性约束）。
- 10 账户 × 500 标的 ≈ 5000 个整数变量，CP-SAT/HiGHS 在秒级可解；若达不到实时性，用"LP 松弛 + 贪心修复到整手"的工程技巧。
- 需要盘中高频重解时，把凸部分切给 **OSQP（warm-start）**。

### 阶段三：按需升级商业求解器
- 触发条件：MIP 求解时间不可接受、或问题规模上到万级变量。
- 优先试 **MindOpt 免费云 API**（0 元验证国产求解器水平）→ 对比 **COPT**（国产商业，价格远低于 Gurobi，联系销售）→ 预算充足再上 **Gurobi**（学术免费，若团队有高校资源可先用）。
- 半定规划（SDP，如稳健组合优化）才需要 Mosek。

### 明确不建议
- 一上来就买 Gurobi（原型阶段开源完全够）；
- 一上来就对标 Barra/Axioma（那是绑定风险模型订阅的机构产品，自研 + 国产求解器是 A 股私募的主流路线）；
- 用开源通用求解器硬扛**亚秒级实时 MIP**（该用 LP 松弛 + 启发式，或把问题改造成凸的）。

## 6. 合规注意（A 股多账户程序化交易）

沪深北交易所《程序化交易管理实施细则》已于 **2025 年 7 月 7 日施行**（[上交所原文](http://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20250612_10781696.shtml)）：

- **高频交易认定门槛**：单账户每秒申报/撤单合计 ≥ 300 笔，或单日申报/撤单合计 ≥ 20000 笔（达标需额外报备并接受差异化监管）；
- 程序化账户需按规定**报备**（账户、策略类型、技术系统信息）；
- 重点监控四类异常：瞬时申报速率异常、频繁瞬时撤单、频繁拉抬打压、短时间大额成交。

**对求解器设计的含义**：多账户分配模型里应把"每账户申报频率/笔数"作为显式约束写进去（不只是为了合规，也为了避免触发交易所异常交易监控）。多账户拆单时尤其注意"多个账户对同一标的同向申报"可能被合并视作程序化异常行为。
