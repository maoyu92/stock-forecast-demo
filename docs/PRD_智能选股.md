## 1. 背景与目标

项目当前提供"单只股票的多因子 TimesFM 走势预测"。本次新增一个独立的**"智能选股"**页面：从全市场 A 股中，按照可选择的选股方法自动筛选出候选股票，作为预测功能的上游入口，形成"**先选股 → 再预测**"的闭环。

设计来源为两份材料：

1. **《早盘摇钱树选股法（秘籍）.docx》**（内容完整可读）：即"量比选股法"，包含完整的筛选流程（量比排行 Top30 → 涨幅 1%~5% → 剔除 ST/非主板 → 人工精选）与 6 条精选要点（现量大、上涨趋势、前日涨停封板、压力位远、MACD 红柱/金叉、缺口回补节奏、风险收益比）。
2. **《游资 私募 险资 庄家.tn6》**：通达信**完全加密**公式文件。经调研，该格式无公开解密方法（仅存在闭源破解工具，涉及公式作者知识产权，不宜破解）。本 PRD 采用**主题近似**方案：以其"游资/私募/险资/庄家（主力资金动向）"为主题，用公开的主力资金类指标重建一个效果类似的选股方法。**若你手头有该公式的明文源码，后续可直接替换修正。**

核心目标：

- **G1**：上线"智能选股"独立页面，V1 内置 2 个选股方法，用户可自选方法并调整参数后一键选股。
- **G2**：建立**选股方法注册机制**（策略插件化），后续新增方法只需注册新策略，不改页面框架。
- **G3**：选股结果可与现有预测页联动（一键切换到预测）。

## 2. 用户故事

- 作为用户，我打开"智能选股"页，选择"摇钱树·量比选股法"，保持默认参数，点击"开始选股"，等待 10~60 秒，看到一张候选股票表（含每只股票命中的因子明细和综合得分）。
- 作为用户，我可以调整参数（如量比下限、涨幅区间、是否要求前日涨停），重新选股。
- 作为用户，我对某只候选股感兴趣，点"去预测"，系统自动跳到"预测"页并带入该股票。
- 作为用户，我可以切换到"主力动向"方法，用另一套逻辑选股。
- 作为用户，我可以把一次选股结果保存下来，之后在结果列表里回看。

## 3. 选股方法定义（核心）

### 3.1 方法一：摇钱树·量比选股法（V1 主打，源自 docx 全量化）

> 原方法是 9:25–9:30 集合竞价期间手工操作。系统化为**收盘后快照口径**（见 §7 数据口径说明），并保留盘中运行能力。

#### 第一层：市场快筛（全市场 ~5000 只 → 约 30~80 只）

| # | 规则（源自原文） | 量化实现 | 默认参数（可调） |
|---|---|---|---|
| F1 | 量比从大到小排列，取前 30 | 东财全市场快照（实时含"量比"字段）按量比降序取 Top N | N=30（范围 10~100） |
| F2 | 涨幅超过 5% 删除，低于 1% 删除 | 快照"涨跌幅" ∈ [1%, 5%] | 下限 1%、上限 5% |
| F3 | ST、*ST 全部删除 | 股票名称含 "ST" | 固定开启 |
| F4 | 30/68/83 开头全部删除 | 仅保留沪主板 60 / 深主板 00 开头 | 固定开启（可放开） |

#### 第二层：深度精选（对 Top N 逐只拉日 K 计算，多因子打分排序）

| # | 原文要点 | 量化实现 | 评分权重（默认） |
|---|---|---|---|
| S1 | 现量一定要大，几千几万优先 | 量比（快照）归一化打分 + 成交额 ≥ 1 亿元过滤 | 20% |
| S2 | 近期趋势必须是上涨趋势 | 收盘价 > MA5 > MA10，且 MA20 近 10 日斜率向上；满足越多得分越高 | 20% |
| S3 | 必须前一交易日涨停封板 | 上一交易日：涨幅 ≥ 9.8% 且 close == high（封板）；**默认硬条件**（可关闭降为加分项） | 硬条件 / 关闭后 15% |
| S4 | 压力位较远优先 | 压力位 = 近 60 日最高价；空间 = (压力位 − 现价)/现价 ≥ 10% 得满分，按比例递减 | 15% |
| S5 | MACD 红柱或刚金叉 | 日线 MACD(12,26,9)：DIF>DEA（红柱）得基础分；近 3 日内金叉（DIF 上穿 DEA）得满分 | 15% |
| S6 | 缺口回补"慢而稳"最好 | 原文语义为盘中分时行为，**日线数据无法精确量化**。V1 降级实现：识别近 5 日是否存在未回补的向上跳空缺口（今日 low > 昨日 high），存在则加分 | 10% |
| S7 | 风险收益比 | 近 20 日波动率越低、压力位空间越大，得分越高 | 5% |

- 综合得分 = Σ(因子得分 × 权重)，0~100 分，按得分降序输出。
- S3 作为硬条件时若命中股票不足，前端提示"可关闭'前日涨停'硬条件扩大范围"。
- 每只结果股展示**因子命中清单**（如：✅前日涨停 ❌MACD 未金叉），用户能看到"为什么入选/落选"。

### 3.2 方法二：主力动向（V1 一并交付，tn6 主题近似）

> 说明：tn6 文件完全加密无法还原源码，本方法基于公开的主力资金类指标近似其"游资/庄家"主题，参数为经验值，后续可与你核对校准。

| # | 因子 | 量化实现 | 权重 |
|---|---|---|---|
| M1 | 连续放量 | 近 3 日成交量均 > 5 日均量的 1.5 倍 | 20% |
| M2 | 量价齐升 | 近 3 日收盘价上涨且成交量递增 | 15% |
| M3 | 活跃换手 | 快照换手率 ∈ [3%, 15%] | 15% |
| M4 | 突破形态 | 收盘价创近 20 日新高（突破平台） | 20% |
| M5 | 主力净流入 | 东财个股资金流（akshare）近 3 日主力净流入为正；仅对预筛后的小集合逐只拉取 | 30% |
| — | 基础过滤 | 与方法一 F2/F3/F4 相同（剔除 ST、非主板；涨幅区间参数化，默认放宽为 0%~7%） | 硬条件 |

### 3.3 策略注册机制（可扩展架构）

- 后端维护**策略注册表**：每个方法 = `{id, 名称, 描述, 参数 schema（名称/类型/默认值/范围）, 筛选函数(快照集合 → 候选集) , 打分函数(K线 → 因子明细+得分)}`。
- `GET /api/screener/strategies` 返回方法列表与参数 schema → **前端动态渲染参数表单**，后续新增方法前端零改动。
- 新增方法 = 后端新增一个策略文件并注册，符合"后期加更多选股方法"的诉求。

## 4. 功能需求（页面与交互）

### 4.1 页面：智能选股（新增 Tab，置于"预测"之后）

1. **方法选择区**：策略下拉/卡片（显示方法名 + 一句话描述 + 数据口径标签）。
2. **参数区**：按所选方法的参数 schema 动态生成（数字输入/滑块/开关），提供"恢复默认"。
3. **操作区**："开始选股"按钮（运行中显示 loading 与已耗时，禁用重复点击）、"保存本次结果"。
4. **结果区**（antd Table）：
   - 列：排名、代码、名称、现价、涨跌幅、量比、换手率、综合得分、命中因子摘要、操作（"去预测"、"看K线"弹窗）。
   - 支持按得分/量比排序、导出 CSV（前端生成）。
   - 空结果时给出原因提示（如"硬条件过严，建议关闭'前日涨停'"）。
5. **历史结果**：页内 Tab 或抽屉查看已保存的选股记录（时间、方法、参数快照、结果）。
6. **免责声明**：页面底部固定提示"选股结果由历史数据量化规则生成，仅供研究参考，不构成投资建议"。

### 4.2 与预测页联动

- 结果行"去预测"→ 切换到"预测"Tab 并自动填入该股票（App 层提升一个 `presetCode` state 传给 `PredictPage`，小改造，不引路由库）。

## 5. API 设计（遵循现有 FastAPI 模式）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/screener/strategies` | 策略列表 + 参数 schema |
| POST | `/api/screener/run` | 执行选股。body：`{strategy_id, params, save}`；返回：`{run_id, strategy_id, generated_at, market_snapshot_time, results:[{code,name,price,pct,turnover,volume_ratio,score,factors:[{id,name,hit,score,detail}], extras}]}` |
| GET | `/api/screener/runs` | 已保存的选股历史列表 |
| GET | `/api/screener/runs/{run_id}` | 单次选股结果详情 |
| DELETE | `/api/screener/runs/{run_id}` | 删除历史记录 |

- 新增 `backend/app/routers/screener.py`（照 stocks.py 风格）、`backend/app/services/screener/`（registry + indicators + 各策略模块）、`schemas.py` 增加请求模型、`db.py` 增加 `screen_runs` 表（参数与结果存 JSON 文本，照 `forecast_history` 模式）。
- 错误处理沿用约定：400 参数错误 / 502 数据源异常，中文 detail。

## 6. 技术方案与性能设计

### 6.1 数据流（两级漏斗，控制耗时）

```
全市场快照（东财 ak.stock_zh_a_spot_em，一次请求，含实时价/涨跌幅/量比/换手率）
   → 第一层规则快筛（毫秒级内存过滤 + 量比排序 Top N≈30）
   → 逐只拉日K（baostock，复用 datasource.fetch_kline + 10min 缓存；N≈30，约 10~30s）
   → 指标计算（pandas 手写：MA/MACD/涨停/压力位/缺口；不引入 talib）
   → 打分排序 → 返回 + 可选落库
```

### 6.2 关键决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 指标库 | pandas 手写（MA/EMA/MACD 等，约百行） | 现有依赖无 talib；容器内编译 talib 麻烦；不新增 pandas-ta 依赖 |
| 全市场行情 | 新增东财快照接口（akshare 已是现有备源依赖） | baostock 无实时快照；逐只串行拉 5000 只 K 线不可行（>15 分钟） |
| 执行模式 | V1 同步接口（nginx 超时 600s 足够），加进程内锁防并发重扫 | 改动最小；异步任务队列列为二期 |
| 缓存 | 快照内存缓存 5min；K 线沿用 10min 缓存；选股结果落 SQLite | 防重复请求打爆数据源 |

### 6.3 数据口径说明（重要）

- 原文是**集合竞价实时**场景；系统 V1 以**最近交易日收盘数据**为准计算深度因子（趋势/涨停/MACD/压力位）。东财快照在交易时段内为实时数据，故量比/涨跌幅/换手率两层筛选用实时口径，页面标注快照时间。
- 主板涨停幅度 10%；因四舍五入，判定用 `涨幅 ≥ 9.8% 且收盘=最高`。

## 7. 范围与里程碑

**V1（本次实施）**：方法一（完整量化 + 打分）、方法二（近似实现）、策略注册架构、智能选股页面（选方法/调参/结果表/CSV 导出/保存与回看）、去预测联动、免责声明。

**二期候选（不在本次范围）**：盘中异步任务与进度推送、更多主力数据源（龙虎榜、筹码分布）、回测模块（选股结果的历史胜率统计）、方法三+（用户提供新策略材料后接入）、预测页打通"批量预测选股结果"。

## 8. 风险与待确认问题

| # | 风险/问题 | 应对 |
|---|---|---|
| R1 | 东财快照接口（`stock_zh_a_spot_em`）依赖 akshare 版本与外网连通性 | 实施第一步先写连通性验证脚本；失败则降级为"收盘后用 baostock 全量日 K 预筛（耗时更长）" |
| R2 | tn6 无法解密，方法二与原公式逻辑可能有差异 | 已按公开指标近似并标注；如你有公式明文可直接替换 |
| R3 | 打分权重主观（S1~S7） | 权重做成参数（默认值见 §3.1），前端可调 |
| R4 | 缺口回补因子日线近似不精确 | V1 降级为缺口存在性加分项，已在 §3.1 说明 |
| R5 | 全市场扫描首跑耗时 10~60s | 两级漏斗 + 缓存 + loading 提示；二期异步化 |

**请你确认的点**：① 方法二"近似实现"是否可接受进 V1（或只上方法一）；② 数据口径按"收盘快照 + 盘中实时量比"是否满足；③ 结果保存/回看是否需要；④ S3"前日涨停"默认作为硬条件还是降为加分项。
